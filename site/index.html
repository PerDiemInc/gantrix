Agents that work the plan.

Give Gantrix a goal and a team of agents with skills. It plans the work as steps that depend on each other, runs whatever is ready in parallel, checks every result, and keeps going until the goal is met. It runs entirely on your machine, with open-source models.

Get started

Your first task in about 10 minutes

Most of the time is the model download. Everything runs on your laptop; nothing leaves it.

  1. 1

    Install and configure

    npm run setup creates .env with a random API token. db:migrate prints “Migrations applied.”

    git clone git@github.com:PerDiemInc/gantrix.git && cd gantrix
nvm use
npm install
npm run setup
npm run infra:up      # Postgres :15432, Valkey :16379
npm run db:migrate
ollama pull qwen3:8b  # the default model, about 5 GB
  2. 2

    Start Gantrix

    Three terminals, one command each. The worker prints “Gantrix worker ready”.

    npm run dev:api      # API on 127.0.0.1:4700
npm run dev:worker   # runs plans, steps and judges
npm run dev:web      # dashboard on 127.0.0.1:4701
  3. 3

    Open the dashboard

    Go to http://127.0.0.1:4701 and paste your token once. Print it with:

    npm run token
  4. 4

    Add a skill and two agents

    The planner reads each agent's description to decide who does what, so make it specific.

    npm run gantrix -- skills add examples/skills/workspace-files
npm run gantrix -- agents add researcher -d "Collects facts and writes notes" -s workspace-files --max-concurrency 2
npm run gantrix -- agents add editor -d "Turns notes into a polished summary" -s workspace-files
  5. 5

    Run a task

    You see the plan, each step start and finish, and a Gantt chart at the end. Or follow it on the dashboard.

    npm run gantrix -- run "Write tea.md and coffee.md with 3 facts each, then compare.md with a table"
npm run gantrix -- files last compare.md

How it works

Plan, run, judge, repeat

Every task goes through the same loop. The state lives in Postgres, so you can stop and restart the worker at any point and the task picks up where it was.

  1. 01 · plan

    Split the goal

    The planner reads the goal and your agents' descriptions and returns steps with dependencies. Bad plans go back to it with the errors.

  2. 02 · schedule

    Start what's ready

    Every step whose dependencies are done starts, within each agent's limit and the worker's model slots.

  3. 03 · run

    Do the work

    The step's agent uses its skills' tools in the task's own folder, up to 25 model turns.

  4. 04 · judge

    Check the result

    A judge compares the reply and the files written against the step's “done when”. Rejected steps retry with the feedback.

  5. 05 · replan

    Change course

    A step that keeps failing triggers a new plan that keeps the finished work and routes around the problem.

  6. 06 · finish

    Check the goal

    When every step passes, the judge checks the goal itself. Budgets for tokens, time and replans stop runaway tasks.

Skills

A skill is a folder with a SKILL.md

Plain Claude skills work as they are. Gantrix reads a few extra keys: which built-in tools the agent may use, MCP servers to start, and which tools can run without asking.

Installing a skill copies it and records a checksum, so editing your original folder never changes what runs. Bump the version to update it.

Safety

You stay in the loop

  • Only the step that needs you pauses. Approve or deny on the dashboard, in gantrix tail, or with gantrix approve. The rest of the plan keeps running.
  • Shell isn't sandboxed. It can do anything your user account can, so it always asks, and no skill can turn that off. Read every command before you approve it.
  • Web pages can talk back. Fetched text can try to steer an agent. Approval is where you catch it.
  • Local only. The API listens on 127.0.0.1 and needs your token on every request; tokens are never accepted in URLs.
  • No secrets for tools. Shell commands and MCP servers don't get the server's environment, so they can't read the token or database password.
  • Confined files. File tools can't leave the task's folder, through .., absolute paths or symlinks.
